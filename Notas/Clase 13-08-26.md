Esto se hace de esta manera para manejar la complejidad del sistema

**Cohesion y Acoplamiento**

Un componente concentra responsabilidades muy relacionadas. Deseable

Dos componentes comparte una estructura de datos global. Evitable

Un flujo hace decenas de llamadas finas entre dos componentes. Evitable


**Modelo** es una representación del sistema de acuerdo a una perspectiva

**Vista** es una proyección de uno o mas modelos de acuerdo a un punto de vista

**Punto de vista** es la definicion de una vista contenido, significado y representacion (lenguajes, tecnicas de modelado)

**Vistas PUD (Proceso Unificado de Desarrollo)**
Modelo 4+1

Vista de Diseño (1): Clases, interfaces, colaboraciones (Parte Estatica Diagrama de clases o Diagrama de Componentes, Parte Dinamica con Diagrama de Secuencia)

Vista de Implementacion (3): Componentes

Vista de Despliegue (4): Nodos

Vista de Proceso (2): Clases activas

Vista de Caso de Uso (La vista +1, es la primera que se hace): Vista arquitectonica de la funcionalidad.

Sistemas Distribuidos
Los procesos del sistema se distribuyen en mas de un procesador por mas que esten en una misma maquina. Conectados por red

Caracteristicas:
Se pueden compartir recursos
No esta centralizada la informacion por lo que tolera mejor los fallos
Concurrencia

Desventajas:
Cada vez mas complejos
Manejabilidad mas dificil
Impredecible
Dificil de asegurar
